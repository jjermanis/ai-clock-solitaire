Version 01.01	28 minutes dev	1 minute CPU	6 minutes test		35 minutes

Another birthday gift: I wanted to create a game from a solitaire I played as
a young child. The trick: I did not know the name, and I only remembered a few
details of the game. I provide the details I did know to Gemini. It suggested
that the game was Clock Solitaire. I am near certain that's right. This is the 
game that we'll create.
Had some interaction with Gemini on the details of implementation. In
particular, I provided the HTML file I created for Klondike. That would be
used for the graphics in Clock.
The initial version game out well. I was expecting the cards to be held at
angle, lining up with the angle on the clock. After seeing this version,
with all cards vertical, I don't think I want to do it. It does nothing to
change the game, and would make cards easier to read. The only thing I see:
removing the Undo button. It was there from the Klondike game. In this one,
there is always only one choice. No point to having an Undo. There is also
a defect, with the screen view needing work.


Version 01.02	13 minutes dev	1 minute CPU	4 minutes test		53 minutes

One of the defects I noticed was significant. The game did adjust dynamically
in size, based on the available size. However, it would cut-off space in 
different ways. On a large screen, the text at the top would not be seen.
On a small monitor, the buttons at the bottom would be hidden. You could
change the size of the browser to see this changes live. Not good.
I asked Google to fix, including my standard to show where to make the 
changes. It provided a fix describing the issue, the change... and the
entire source code. I reject that. I looked in source control - there
were a lot of changes that were made. I don't want to do that. I asked
Gemini that I wanted to know clearly when I could make the changes, and
what to put there. That was done; the fix worked well.


Version 01.03	8 minutes dev	0 minutes CPU	1 minutes test		1 hour 2

I had played the game several times. I never won. That's not usual: the
odds are 1 out of 13 to win the game. I asked Gemini to create a test 
version that will win. I wanted to confirm that the game detected winning.
It does this in a straight forward way. The cards are stacked by suit, in
order from 1 to Queen, then to King. This is done for all 4 suits. This
guarantees that the player will win. I tried this. It did work, and the
game confirmed that the player won.
I am not going to put that in the main game. I don't think it's necessary.
I'll commit it as a separate test_win version of the game.
Funny side note. After making this test case... the next (real) game I
played, I won on the first try.


Version 01.04	19 minutes dev	1 minute CPU	3 minutes test

Doing cleanup for the final version before release.
I removed the Undo Button. It was only there because the UI was copied from
another solitaire game. It has zero purpose here: no options ever on move.
It was easy, and drops about 70 LOC.
I added the MIT License to the UI. No help was needed from Gemini. It's 
standard, and I copied it exactly from the other solitaire game.
I wanted to add a little bit of an offset to the face-up decks, to give
some indication of how much they have played. Getting the current settings
from Gemini took a bit of extra work. But the change was made. Not ideal,
but we need the space for a lot of stacks. I'm alright with this.
